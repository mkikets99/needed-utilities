AD-MOB.TXT — AdMob integration recipe for The Needed Utility (S-12)
================================================================================
Purpose: everything needed to wire banner + interstitial ads into the app in
one pass. Prepared 2026-11-10. When implementing S-12, follow this file top
to bottom — it assumes the codebase state at v7.

User-specified behavior (2026-11-10):
  * Banner ad on the home screen.
  * Full-screen (interstitial) ad triggers when switching to a tool for the
    5th time. "Switch" = any navigation from home into a tool screen.
    Closing and re-opening the SAME tool also counts as a switch.
    So: every 5th tool open (5th, 10th, 15th, ...) shows the interstitial.

Pro gate: when S-13 lands, ALL of this is skipped for Pro users
(see section 7). Keep the gate in mind while wiring.

4. ARCHITECTURE — new file: app/src/main/java/.../monetization/Ads.kt
--------------------------------------------------------------------------------
Create `monetization/` package with one object, e.g.:

    object AdManager {
        // --- interstitial frequency rule ---
        private var toolOpenCount: Int = 0        // in-memory, per app session
        const val INTERSTITIAL_EVERY = 5

        fun onToolOpened(): Boolean {             // call on EVERY tool navigation
            toolOpenCount++
            return toolOpenCount % INTERSTITIAL_EVERY == 0   // -> show ad
        }

        // --- interstitial loading ---
        // Load eagerly after app start AND after each show (ads are one-shot).
        // lateinit InterstitialAd + AdRequest; full-screen content callback
        // navigates/restores state after dismissal.

        @Composable

            //   adUnitId = BANNER_ID; setAdSize(AdSize.BANNER); loadAd(AdRequest) } })
        }
    }

Notes:
  * Tool-open counter is SESSION-scoped (in-memory). "Closing and opening
    the same tool counts as a switch" is satisfied because every call to
    onToolOpened() counts, regardless of which tool.
  * Interstitial show timing: load before needed (never on main-thread
    block); if not loaded when due, skip silently (never block navigation).
  * After each show, immediately request the next interstitial.

5. INSERTION POINTS (existing files)
--------------------------------------------------------------------------------
a) NeededUtilityApp.kt — the HOME composable route:
       onToolClick = { tool ->
           val showAd = AdManager.onToolOpened()
           navController.navigate(tool.route)
           if (showAd) AdManager.showInterstitialIfReady(activity)
       }
   (Every tool entry goes through onToolClick — home -> tool only. This is
    exactly the "switch" the user described; re-entering re-triggers it.)

b) ui/home/HomeScreen.kt — banner placement:
       Add `AdManager.HomeBanner()` at the BOTTOM of the Scaffold content
       (below the LazyColumn, inside the Scaffold's content lambda), so it
       sits above the system nav bar and never overlaps the tool grid.

c) MainActivity.kt — initialize Mobile Ads SDK once:
       MobileAds.initialize(this)   // in onCreate
       (needed for both banner and interstitial)

d) AndroidManifest.xml — see section 2.

--------------------------------------------------------------------------------
6. FREQUENCY / UX RULES (AdMob policy + user spec)
--------------------------------------------------------------------------------
  * Show interstitial on every 5th tool open (5, 10, 15, ...).
  * Never show an interstitial twice in a row for the same trigger; never
    on app cold start; never inside a tool flow (only on switch).
  * Ads must never overlap tool content; banner only on home.
  * User must always be able to close interstitials (system back works).
  * If AdManager fails to load, the app must behave exactly as before
    (offline-first promise still holds for all tools).
